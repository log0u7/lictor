# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- `lictor acquire` surfaces the profiler's stderr in the failure
  message (the profiling subprocess used to die silently and the error
  said nothing).
- The gemspecs build identically from any working directory: `files`
  globs anchor to `__dir__` and lictor-mcp reads its version from
  `lib/lictor-mcp/version.rb`.

### Added

- `lictor build` + `Lictor::PayloadBuilder`: the asploit inheritance.
  The offset is MEASURED (a cyclic pattern crashed under the debugger -
  rip first, then the rbp slot a leave;ret epilogue betrays), the
  return address comes from the facts (win_symbol / the jmp rsp-esp
  gadget), the assembly follows the selected technique, and the result
  is a payload file the run sends as-is: `lictor run --payload`.
  No more brute-forced offsets in the exploits. `lictor run` failure
  is truthful now: the lab exploit raises when the flag does not come,
  so ronin's exit code can no longer lie about the success.
- The ronin subprocess runs in a MINIMAL environment (env -i
  semantics): any surviving bundler hook froze the gem set to lictor's
  bundle, where ronin-exploits deliberately is not.
- The README demo gif (docs/art/demo.gif, generated by hand with
  vhs - docs/art/demo.tape has the recipe; never CI-generated, a bot
  that commits the gif is a push conflict waiting to happen).
- `Lictor::Suggestion` + the `suggest_facts` MCP tool: the agent
  enriches the fact base with hypothesis facts. The closed schema is
  the whitelist (no applicable() exists to forge), augure re-decides
  on the merged base, the delta comes back to the agent, and the trail
  records who proposed what and what changed.
- Taught techniques finally participate in decisions: `plan`, `run`
  and the MCP plan tool load the packs directory (config `packs:`,
  default `packs/`), the full armor runs at load time, and pack priors
  fill the gaps of the prior table without ever clobbering an
  outcome-adapted entry - the loop keeps learning on top.
- `lictor acquire`: the nmap -> binary bridge - local copy or http
  download, ELF-checked before profiling, recorded. The demo's manual
  curl is gone.
- `lictor verify`: the differential - the fuzzer's longest crash input
  goes to the remote service; the remote faults like the local model =
  the facts gain `verified("remote")` (modeled-from-ELF vs
  remote-verified).
- The lab: four vulnerable services, four fact bases, four different
  decisions (ret2func / ret2plt / shellcode / fmtstr_write) with one
  lab exploit each; demo.sh replays the whole chain for all four.
- A CI release workflow: a `v*` tag builds the two gems and pushes
  them to rubygems.org with a scoped key from a secret.

## [0.2.0] - 2026-10-03

### Added

- `lictor plan <binary>`: ELF magic detection profiles the binary
  through the augure-profile subprocess (trailed), then decides. A
  `.facts` file passes through unchanged. One command from binary to
  decision.
- `lictor scan`: nmap as a gated, trailed action against an allowlisted
  host (subprocess; --nmap override for testing). Scans appear in
  `runs` and in the engagement report.
- Network facts: service/software_version/remote emitted from nmap
  scans; remote technique packs match them like binary facts.
- Fuzzing and triage (augure-profiler): RubyMutator built-in + radamsa
  optional; GdbBackend (real run covered), RizinBackend, LldbBackend;
  `lictor fuzz` gated and trailed.
- Executor interface: ManualExecutor (default, handoff) + RoninExecutor
  (discovery from the operator's repos; fabricated names refused).
- `lictor run`: the closed loop - decide, execute, outcome, re-decide -
  with budgets and interactive confirmation.
- Consent tokens: `lictor authorize <target>` - human-typed, TTL'd,
  trail-recorded.
- lictor-mcp (4th gem): scan/plan/execute/validate_pack tools with
  server-side gates and token validation.
- `lictor rule validate|install|list`: teach augure techniques as data
  (packs), full armor + corpus guard.

### Removed

- `--i-am-authorized` and `--target` flags: security theater. A flag
  can be typed by reflex, by a script, or by anyone with shell access -
  it proves nothing and taxes the legitimate user. Authorization is the
  allowlist artifact (explicit host[:port] entries, colon-delimited
  prefix match so .1 cannot pass for .10) plus the trail. A future
  execute command will confirm interactively (show the recipe, type the
  target), never through a flag.

## [0.1.0] - 2026-10-02

### Added

- Project scaffold: authorization gates design, handoff-default README,
  CI (gitleaks), MIT license, AGENTS.md.
- Gates: explicit allowlist (wildcards rejected), per-run consent flag,
  allowlist-checked `--target`.
- Recon: nmap XML to target inventory via ruby-nmap; `lictor recon`
  prints allowlist candidates (candidates, never authorization).
- Handoff default: augure decision printed as a ronin-exploits recipe
  with mixin hints (Binary / FormatString); exploit names deferred to
  the operator's ronin repos.
- The closed loop: `lictor outcome` records results, outcomes feed the
  augure bandit priors (`Lictor::Priors.from_trail`), the next decision
  adapts - end to end trailed.
- JSONL trail with run aggregation (`lictor runs`).
- Engagement report: auditable markdown (decision, rule provenance,
  outcome) with the claims-discipline line; `lictor report -o`.
